### 안전장치 전: 불통과

`gate.run_gate("dummy", "v2")` 결과는 **불통과**였다. 사유는 하나뿐이었다: `preserved_terms_retention_rate: 0.9722 must equal 1.0`.

누락은 한 문장에서 나왔다. 보존 용어 2개가 겹친 경우다.
- 원문: "주민과 소속 주민등록확인팀장은 … 전자금융업자가 **주민등록증** 진위확인 서비스를 …"
- v2: "주민과 주민 확인 팀장은 … 전자금융 회사에서도 **주민증**을 확인하는 …" → `주민등록증`과 `주민등록`이 모두 누락됐다. 숫자는 같아서 숫자 안전장치에 걸리지 않았다.

### 보존 용어 안전장치

- `Simplifier.simplify_detailed()`는 원문에 있는 보존 용어가 출력에서 빠지면 그 문장만 원문을 돌려주고 `fallback=True`로 표시한다. 숫자 안전장치와 같은 방식이다.
- 판정 함수 `missing_terms()`와 목록(`preserve_terms.txt`)은 `simple_word/terms.py` 한 곳에 있다. 서빙(`simple_word/model.py`)과 교사 검사(`training/checks.py`)가 같은 함수를 import한다. 목록 파일은 `training/`에서 `simple_word/`로 옮겼다.
- 효과:
  - test 186문장 중 출력이 바뀐 문장은 위 1개뿐이다(fallback 18 → 19).
  - parity 고정 입력 20문장 중 3개가 원문으로 바뀌어 `parity.jsonl`을 다시 만들었다. 바뀐 문장: 본인부담금, 주민등록증, 의료급여 수급권자. 이 3개에서 모델이 보존 용어를 빠뜨렸다.

### 안전장치 후: 통과 → champion = v2

`gate.run_gate("dummy", "v2")` 결과는 **통과**다(사유 없음, parity 20/20). 그래서 champion을 v2로 지정했다. 로컬 `models/registry.json`을 `{"champion": "v2", "canary": null, "canary_weight": 0, "shadow": null}`로 썼고, `ModelRouter`가 읽는 것까지 확인했다. 운영 버킷의 `registry.json` 반영은 배포 단계에서 한다. 게이트 기록은 `reports/`에 생겼지만 커밋하지 않았다.

## 해석

- **길이 문제는 해결됐다**: 길이 감소율이 -0.1657에서 -0.0341로 좋아져 기준(-0.10)을 넘는다. 교사(-0.0462)보다도 덜 길어진다. 교사 짝에서 긴 출력과 여러 줄 출력을 뺀 효과로 보인다(v2 출력 중 여러 줄 0개, 1.3배 초과 18개).
- **보존 용어 실패 1문장은 안전장치로 막았다**(총괄 결정). 대가는 fallback_rate 0.0968 → 0.1022이다. 모델 자체가 보존 용어를 지키게 하는 일(학습 짝에서 보존 용어 문장을 더 많이 보게 하기 등)은 남아 있다. parity 20문장 중 3개에서 용어를 빠뜨린 것을 보면 빈도가 낮지 않다.
- **fallback_rate 10.2%**: 숫자가 바뀐 문장 18개와 보존 용어가 빠진 문장 1개는 원문을 돌려줬다. 비율이 v1보다 높은 것은 시간순 test(최근 글)가 숫자가 많은 보도자료 위주이기 때문일 수 있다 [미확인].
- **자동 지표가 못 잡는 뜻 오류는 여전하다.**
  - "최근 30년 중 두 번째로 적었고" → "30년 동안 가장 많은 사람이 다쳤고"는 뜻이 반대가 됐다(숫자 30은 같아서 통과).
  - "(개인포상) … 신분확인 사각지대 해소" → "개인포끼리 간편결제를 …"는 환각이다.
  - 사람 검수 평가셋(T11)이 있어야 이런 오류 비율을 잴 수 있다.
- 좋은 예: "11월 18일, 관계기관 대책회의 열어 기관별 대응태세 최종 점검" → "11월 18일에 관계기관 대책 회의를 열어 기관별로 대응 태세를 최종 확인합니다."
- CPU 지연·메모리는 이 Mac 기준이다. Lightsail에서는 재지 않았다 [미확인]. MPS 학습은 비트 단위 재현이 안 되는 점(T6_V1 "재현성")도 그대로다.

## 배포 크기 (v2 서빙, 2026-11-19)

목적: Cloud Run 메모리 0.5GiB와 1GiB 중 무엇을 쓸지, Lightsail 2GB에서 api+proxy가 여유 있는지 정하기.

```
docker build -t simple-word:local .
python scripts/footprint.py docker --image simple-word:local --models models --cpus 2 --sentences data/v2/test.jsonl
python scripts/footprint.py native --models models --sentences data/v2/test.jsonl     # 컨테이너 없이 같은 앱
```

**컨테이너 측정은 아직 못 했다.** 이 Mac 계정(pioneer13)에서는 Docker를 쓸 수 없다. `/var/run/docker.sock`이 다른 사용자(camp-lee)의 OrbStack 소켓을 가리키고, docker 실행 파일도 권한이 없다(`permission denied`). 그래서 아래 표는 같은 uvicorn 앱(`api.main:app`, champion v2, `MAX_CONCURRENT_SIMPLIFY=2`)을 **로컬 프로세스로 돌린 값**이다. `scripts/footprint.py docker`는 이 환경에서 한 번도 돌려 보지 않았다.

| 항목 | 로컬 프로세스 (2회) | 컨테이너 `--cpus 2` |
|---|---|---|
| 시작 → 첫 `/health` 200 | 0.60 / 0.73 s | 미측정 |
| 유휴 메모리 (첫 요청 뒤 3초, RSS) | 351 / 356 MiB | 미측정 |
| 처리 중 최대 메모리 (100문장 문서 3건 + 1문장 요청 200건, 50ms 표본 RSS) | 364 / 370 MiB | 미측정 (`memory.peak`로 잴 예정) |
| 100문장 문서 1건 | 4.4~5.1 s (문장당 44~49 ms) | 미측정 |
| 1문장 요청 p50 / p95 (순차 100건) | 47 / 84~85 ms | 미측정 |
| 1문장 요청 p95 (동시 2건, 100건) | 106~108 ms | 미측정 |

- 환경: Apple M5 Ultra(30코어), macOS, Python 3.12.15, onnxruntime 1.32.0. 이미지는 Python 3.11-slim(linux)이고 Cloud Run·Lightsail은 x86일 수 있다. CPU 시간은 그대로 옮길 수 없다 [미확인].
- `Simplifier`는 세션마다 `intra_op_num_threads = 1`이라 요청 하나가 코어 1개를 쓴다. 동시 처리는 최대 2건(`MAX_CONCURRENT_SIMPLIFY=2`)이다. 그래서 `--cpus 2` 제한이 있어도 순차 지연은 거의 그대로이고, 동시 2건일 때만 영향이 있을 것으로 본다 [추정].
- 메모리는 거의 모두 모델(ONNX 인코더·디코더 INT8 164 MB를 메모리에 올림)과 Python·onnxruntime이다. 100문장을 처리해도 유휴보다 약 15 MiB만 늘었다.

판단(로컬 값 기준, 컨테이너 측정으로 확인 필요):
- **Cloud Run 0.5GiB(512 MiB)는 빠듯하다.** 최대 약 370 MiB면 여유가 140 MiB쯤이다. Cloud Run은 컨테이너 안 파일 쓰기(`/app/logs/requests.jsonl`)도 메모리로 센다. 로그가 쌓이면 계속 줄어든다. 모델이 2개 올라가면(canary·shadow) 바로 넘는다. **1GiB를 권한다.**
- **Lightsail 2GB는 여유가 있다.** api 약 370 MiB + nginx proxy 수십 MiB에 OS·Docker를 더해도 1GB 안쪽으로 본다 [추정]. canary 컨테이너를 같이 띄워도(모델 하나 더, 약 +370 MiB) 2GB 안에 든다 [추정].
- 시작 시간: 로컬에서는 1초 안이다. 이미지 내려받기와 Cloud Run 콜드 스타트는 여기에 들어 있지 않다.
