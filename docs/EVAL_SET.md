### 검수 규칙 v2

1. **공공기관 쉬운 말 기준으로 적극적으로 바꾼다.**
   - 어려운 한자어·행정 용어·외래어는 반드시 쉬운 말로 바꾼다. 국립국어원 어려운 용어 사전(`nikl_dict`)의 대안어를 먼저 쓴다(플랫폼→장치 틀, 클러스터→협력 단지, 제네릭→복제약, 라운드 테이블→원탁회의).
   - 다만 「」·‘’ 안의 사업·법령·행사 이름은 그대로 둔다(예: 「K-제약바이오 프론티어기업」, ‘WHO SAFER 이니셔티브’).
2. **긴 문장은 짧게 나눈다.**
   - 원문이 40자 이상이고 내용이 여러 개면 2~3문장으로 나눠도 된다. 한 문장에 한 가지 내용을 담는다.
   - 제목·항목 조각(명사로 끝나는 원문)은 '~합니다' 문장으로 풀어도 되고, 짧은 명사구로 남겨도 된다.
3. **바꾸지 않는 것**
   - 숫자·날짜·금액은 원문 표기 그대로 쓴다(‘26.6.25, 3,705억 원, 1천만 원). 원문에 없는 숫자를 새로 넣지 않는다(예: '연간'을 '1년에'로 바꾸지 않음).
   - 보존 용어(`preserve_terms.txt`)와 기관명·인명·고유 명칭, 영어 약어는 그대로 둔다. 약어에 원문의 우리말 풀이가 있으면 함께 둔다.
4. **뜻을 바꾸지 않는다.** 원문에 없는 사실을 넣지 않고, 대상·조건·기간·부정을 빼지 않는다. 덜 중요한 꾸밈말은 줄여도 된다.
5. **길이** 정답은 원문 길이의 1.3배 이하로 쓴다. 원문이 40자 미만이면 1.8배까지 쓴다(제목을 문장으로 풀 때).
6. **문장당 정답 2개**를 쓰고, 둘은 서로 다른 표현으로 쓴다(낱말 선택·문장 나누기·어순). 원문과 같은 정답이나 두 정답이 같은 경우는 금지한다(200건 모두 확인).
7. 말투는 '~합니다'체로 쓴다. 인용문은 큰따옴표를 그대로 두거나, '~라고 말했습니다'로 풀어 쓴다.

400개 정답을 모두 자동으로 확인했다.
- **숫자:** (값, 단위)가 원문과 같다. `training.checks`의 숫자 검사는 바로 앞 낱말(anchor)까지 비교한다. 정답은 낱말을 바꾸므로 정답 검사에는 값과 단위만 쓴다.
- **보존 용어·「」 이름:** 남아 있다.
- **길이:** 규칙 5 안이다.
- **같은 정답 금지:** 원문과 같은 정답, 서로 같은 두 정답이 없다.
- **조건 휴리스틱:** `checks`의 기한·조건·대상 낱말 휴리스틱(예: '까지' 유무)은 정답에서 여러 번 걸렸다. 걸린 행을 하나씩 읽어 뜻이 같다고 판단해 그대로 두었다.

### 코드

- `training.evaluate.references(row)`는 `references` 목록을 읽는다. 예전 형식(`ref`·`tgt` 한 개)도 읽는다.
- **SARI(어절·형태소):** Xu et al. 2016 다중 참조 방식이다. 원문·출력 n-gram 개수에 참조 수를 곱하고, 참조들의 n-gram 개수를 더해 비교한다. 참조가 1개면 이전 값과 같다.
- **`bert_score_ref`:** 정답마다 F1을 내고 그중 최댓값을 그 문장 점수로 쓴다.
- **게이트:** `data/eval/eval_set.jsonl`의 SHA-1을 그대로 읽어 champion·후보가 같은 지문인지 본다. 새 파일은 새 지문(`8922190f…`)으로 평가했다. 보고서 맨 위 `Evaluation set SHA-1`에서 확인할 수 있다.

### 다시 만들기

`data/eval/`(gitignore)의 입력 세 개로 평가셋 v2를 그대로 다시 만든다. 같은 입력이면 SHA-1 `8922190f`가 나온다(확인함).

```bash
# 1. v1에서 뺀 7자리를 같은 층의 새 문장으로 채움 → data/eval/fill_v2.jsonl (SHA-1 fb5d333e)
python -m training.eval_set fill-v2 --splits data/v2 data/v3-base
# 2. 정답 CSV(id, 원문, 정답1, 정답2[, 정답3], 메모) + v1 + 채움 → data/eval/eval_set.jsonl (SHA-1 8922190f)
python -m training.eval_set build-v2 --v1 data/eval/eval_set.v1.jsonl --fill data/eval/fill_v2.jsonl --csv data/eval/review_v2.csv
```

`build-v2`는 다음 경우 멈춘다.
- 원문 열이 평가셋·채움 문장과 다를 때
- 정답이 2개 미만일 때
- 정답이 원문과 같거나 정답끼리 같을 때

  - 정답이 원문의 숫자·기관명·보존 용어·고유 명칭을 그대로 담고 있다. 그리고 BERTScore는 토큰 임베딩이 얼마나 겹치는지를 본다. 그래서 내용이 다 들어 있는 원문이 높게 나온다.
  - 어려운 말을 쉬운 말로 바꾸면 임베딩이 오히려 멀어진다(오가노이드 대 인공 장기). 모델은 문장을 나누거나 꾸밈을 줄이면서 정답과 다른 표현을 쓰기도 해서 점수를 잃는다.
  - 그래서 BERTScore는 "뜻을 크게 잃지 않았는지" 보는 하한 검사로만 쓰고, 바꾼 정도는 SARI와 어려운 용어 유지율로 본다.

행 하나에 1분이면 200건을 3~4시간에 끝낼 수 있다 [추정].

## 명령

```
# 1. 후보 200건 (원문·교사 출력·v2 출력·fallback 여부)
python -m training.eval_set candidates --pairs data/pairs.jsonl --splits data/v2 --model models/v2   # → data/eval/candidates.jsonl
# 2. 검수 CSV
python -m training.eval_set export-csv                                    # → data/eval/review.csv
# 3. 검수 끝난 CSV → 평가셋 (src, ref, edited, stratum, doc_id, memo)
python -m training.eval_set import-csv                                    # → data/eval/eval_set.jsonl
# 4. 누수 검사: eval_set_overlap 이 0이어야 한다
python -m training.train --version v2 --pairs data/pairs.jsonl --split time --docs data/docs.jsonl \
  --eval-set data/eval/eval_set.jsonl --check-leakage
```

- 정답(`ref`)은 **고친 쉬운 말**이 있으면 그것이고, 비어 있으면 **제안 쉬운 말**이다. `edited`가 사람이 고쳤는지 표시한다.
- 앞으로 학습할 때는 항상 `--eval-set data/eval/eval_set.jsonl`을 넘긴다. 그러면 `train()`이 평가셋 문장이 train에 들어간 것을 보고 학습을 거부한다(`training/train.py` `leakage`). 지금 후보는 모두 교사 검사에서 탈락한 짝이다. 나중에 교사를 다시 돌리거나 검사 규칙을 바꾸면 이 문장들이 train에 들어올 수 있다.

## 한계

- **문서 단위로는 겹친다.** 200건 중 171건은 train에 쓴 문서에서 나왔다(valid 문서 13, test 문서 16). 문장은 다르지만 같은 보도자료의 다른 문장을 학습했으므로 성능이 실제보다 좋게 나올 수 있다. `--eval-set` 누수 검사도 문장 단위만 본다. 문서까지 떼려면 v2 이후(11-20 이후) 새로 모은 글에서 뽑아야 한다.
- **교사가 탈락시킨 문장만 있다.** 탈락 사유는 length 위주다(200건 중 length 포함 141). 원문이 어렵거나 길어 교사도 실패한 문장일 수 있어서, 평가가 쉬운 문장보다 어렵게 나올 수 있다 [미확인].
- 국어원 용어 층은 19건이라 이 층만의 비율은 오차가 크다.
