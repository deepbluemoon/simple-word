## 4. Ollama 교사 모델 → 짝 생성 → 작은 모델 증류: 현실성 실험

### 4.1 실험 [확인됨: 이 머신에서 실행]

- 공문서 문장 3개(복지 사업 신청 / 과태료 감경 / 수도계량기 동파), temperature 0.2, 같은 프롬프트(정보 유지·쉬운 말·출력만)
- 추가 내려받기: `gemma3:27b`(17GB), `exaone3.5:7.8b`(4.8GB)

### 4.2 판단: 현실적이다 (조건부)
1. **처리량 충분**: gemma3:27b 문장당 ~1.3s → 시간당 약 2,500~2,800 문장 짝, 하룻밤(8h) 2만 건 수준. 96GB 메모리면 더 큰 교사(예: 70B Q4 ≈ 40GB)도 가능 [미확인: 미실험].
2. **품질은 필터 필수**: 모든 모델이 "용어 바꿔치기·정보 누락"을 보임. 짝 생성 뒤 자동 게이트를 둔다:
   - 숫자·날짜·금액·비율 일치 검사(정규식, 예: 100분의 20 ↔ 20% 정규화)
   - 보존 용어 목록(과태료, 기초생활수급자 등 법적 지위 용어는 유지 + 괄호 풀이) — 프롬프트와 검사 모두에 반영
   - 2절 B/A 사전으로 "어려운 용어 잔존율" 측정, 문장 길이·어절 수 감소율
   - 교사 2개(gemma3:27b, exaone3.5) 교차 검증 또는 역질문(원문의 대상·기한·조건이 쉬운 말에 있는지) LLM 판정
   - 일부(예: 200건) 사람 검수 → 평가셋(골드) 고정, parity·게이트 기준으로 사용
3. **학생 모델은 Lightsail 1.9GB RAM에 맞춰야 함** (후보, 모두 [미확인: 미실험]):
   - KoBART 계열(~124M, seq2seq) — CPU 추론 가볍고 짝 데이터 미세조정 쉬움, ONNX/int8 변환 시 수백 MB
   - Qwen3-0.6B / Gemma3-1B를 LoRA 미세조정 후 GGUF Q4(약 0.4~0.8GB)로 llama.cpp 서빙 — 2 vCPU에서 문장당 수 초 예상
   - 학습은 이 머신(Apple GPU, MPS/MLX)에서 수행, 산출물만 버킷 업로드
4. **라이선스 주의** [미확인: 이번에 원문 미확인]: EXAONE 3.5는 비상업 라이선스로 알려져 있어 서비스용 데이터 생성 교사로 쓰기 전 약관 확인 필요. Gemma는 Gemma 이용약관, Qwen3는 Apache-2.0으로 알려짐. 원문 쪽은 AI Hub 데이터(재배포 금지)와 공공누리 유형을 짝 데이터 메타에 기록.
